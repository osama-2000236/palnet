**Trap worth remembering:** the utility is named `bidi-plaintext`, not `text-user`.
tailwind-merge reads any `text-…` class as a text colour and drops it when a real
colour class follows in the same `cx()` call — which silently disabled the fix on
the inbox preview while the message bubble (plain `className`) worked. Confirmed
by reading computed style, not by looking at the screenshot.

## Harness traps (both cost a debugging cycle)

- **`packages/ui-web` edits need a dev-server restart.** The web app consumes the
  kit as source (`main: ./src/index.ts`), and a running `next dev` kept serving the
  pre-edit module — the new class was simply absent from the DOM.
- **`apps/web/messages/*.json` edits need `rm -rf apps/web/.next`.** A plain restart
  is not enough: the client message payload keeps the old snapshot and `t()` renders
  the key path (`employer.emptyDesc`) with a `MISSING_MESSAGE` console error. Read the
  console in the probe before concluding the key is wrong — the JSON on disk was fine.

## Pass 2 pass (same day) — the residual items, closed

The three "out of engineering scope" items from
[screen-critique-2026-07.md](./screen-critique-2026-07.md) §Residual, plus the
mobile action-parity gap. Two of them turned out to be defects rather than
design asks.

### 1. Post actions — web had two dead buttons, not mobile a missing feature

`packages/ui-web/PostCard` rendered five actions; `apps/web/.../PostCard.tsx`
never passed `onRepost` or `onShare`, so **repost and send were `onClick=
{undefined}`** — they had been dead since the component shipped. Copying that
to mobile would have propagated the bug as "parity".

- **Repost** has a real API (`POST`/`DELETE /posts/:id/reposts`) and a real DTO
  field (`viewer.reposted`). Wired on both platforms with optimistic counts.
- **Share/send** is deleted, not built: there is no public post permalink on
  either platform, so the button has nowhere to point. `PostCard.types.ts`
  already states the rule — "a glyph that does nothing is worse than no glyph".
  Both `repost` and `save` now render only when the host wires a handler.

Both platforms land on four actions. Native drops the visible labels past three
(`actions.length > 3`), matching web's `sr-only`-below-`sm` treatment from
finding #6; `accessibilityLabel` still carries the text per MOBILE.md §a11y.

### 2. `/me/premium` persuasion layer — and the promise it was making

The page's own subtitle said **"وألغِ متى شئت"** (cancel anytime). Nothing in
the codebase ever wrote `cancelAtPeriodEnd`; the UI could render the cancelled
state but no endpoint produced it. A trust layer on top of a false headline
claim is worse than no trust layer, so the endpoint came first:

- `POST /billing/me/cancel` — flags `cancelAtPeriodEnd`, idempotent, 404 with
  no active subscription, `private, no-store`, returns the fresh `BillingMe`.
- Cancel control on web (`window.confirm`) and mobile (`Alert.alert` — the OS
  two-button confirm; the account-delete `Modal` idiom is for the irreversible).

Persuasion layer proper: a `recommended` badge (the only badge on the page), a
guarantee line under the CTA, and a three-item trust strip. **Every line is
something the product does** — a real cancel, local rails (bank transfer +
wallets), karama-as-payment. No member counts, no testimonials: we have no real
ones, and inventing them is the one move that destroys the surface it decorates.

### 3. Operator scan-speed layout

Both queues moved from per-row `card` to `flat` container + `row` items, the
composition PR #89 established.

- **`/moderation`** gets bulk select: a select-all checkbox, an `N selected`
  bar, `Escape` to clear, and the row checkbox first in tab order so Tab runs
  select → actions → next row instead of four stops per report. Bulk action is
  **DISMISS only** — the high-volume action a spam flood generates.
  WARN/SUSPEND/HARD_DELETE stay per-row; a bulk account deletion is how a queue
  becomes an incident. The loop is sequential so the 409 "another moderator got
  here first" path stays meaningful.
- **`/billing`** gets the density and nothing else. Both its actions move money
  (MARK_PAID activates a purchase, VOID kills an invoice), so each keeps its own
  confirm.

### 4. Illustration kits

`outline` was already on the admin surfaces; `block` had no caller at all — it
was deleted once in ponytail audit 4 for exactly that, then restored. Rather
than leave it homeless a second time, the three kits are now three registers,
written down in **DESIGN.md §7.5**: `harvest` member-facing, `outline`
admin/operator, `block` failure (`error.tsx`, `not-found.tsx`, the `(app)`
boundary).

### Found while verifying

The **root `not-found.tsx`** — which Next serves for every unmatched path,
including `/ar-PS/<typo>` — was hardcoded English on an Arabic-first product.
It renders outside the `[locale]` segment so `useTranslations` is unavailable;
per BRAND.md the un-localized surface is Arabic. Now Arabic, with `٤٠٤`.
