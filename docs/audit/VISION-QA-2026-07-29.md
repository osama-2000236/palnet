## Fixes

**Deleted rather than kept as a promise.** `/settings/privacy` on web now renders
the read-only privacy contract the native twin has always shown — a warning that
the controls are not wired, the three states as they actually behave, and a
disabled save. The `PrivacySettings` zod schema and eight orphaned message keys
went with the form. Re-add them beside the controller that serves them.

**One password policy** (`Password` in `packages/shared/src/schemas/auth.ts`):
10 chars, upper, lower, digit. `ResetPassword` is gone; register, change-password
and reset all use the same schema, and both clients now validate with
`Password.safeParse` instead of a hand-copied length check — the web security
form was checking `< 8` against a server that wanted 10.

**`AuthShell`** (`apps/web/.../(auth)/_components/AuthShell.tsx`) gives all five
auth screens the logo, eyebrow, title, subtitle and card the native screens have,
plus the login ⇄ register cross-link. The terms checkbox links to both legal
pages.

**`.rtl-mirror` now uses `scale: -1 1`** instead of `transform: scaleX(-1)`. The
individual `scale` property composes with `transform` rather than replacing it, so
`rtl-mirror rotate-90` finally means both things. This was a landmine for any
future caller, not just the legal pages.

**`formatPlace`** (`packages/shared/src/place.ts`) is the one city + country
formatter for both clients. It **pins PS** rather than trusting
`Intl.DisplayNames`, which is not one answer: Node's ICU says "الأراضي
الفلسطينية", Chrome's says "فلسطين", and Hermes may not implement it at all — the
same company page rendered a different country on the server, in the browser and
on the phone. Covered by `place.spec.ts`.

**Mobile gained two real screens.** `settings/security` is now the live twin of
web's (password change, session list with relative last-active times, per-session
and sign-out-others revocation; 2FA keeps its honest "قريبًا"). `employer/new` is
the create-company form mobile never had, so the employer side of the product is
reachable from a phone — and `/employer`'s empty state now says so and links to
it.

Also: profile `Tabs` scroll instead of wrapping (the app shell's own nav pattern,
edge-fade mask included); `/network` rows truncate instead of wrapping their
action; `/onboarding` seeds from `/profiles/me`, filling only fields the user has
not touched; `/employer/new` moved onto the kit and the city picker; 20 strings
rewritten to MSA (admin queues keep the Palestinian register on purpose, per
`screen-critique-2026-07.md`).

## Not fixed, recorded

- **Emulator dark cell needs a retry.** `set-appearance.yaml` failed once mid-run
  ("Bluetooth keeps stopping" system dialog stealing the tap) and once the cell
  was skipped in silence apart from the harness's own failure list. Disabling
  `com.android.bluetooth` on the AVD cleared it.

- **The dev client will redbox `Compiling JS failed: <line>:<col>` and it is not
  your code.** After wiping `%TEMP%\metro-cache` and `adb shell pm clear`, the
  client served a redbox on every launch. It looks exactly like a Hermes syntax
  gap in a dependency. It is not:
  1. `hermesc.exe -emit-binary` — the same compiler the app ships
     (`react-native/sdks/hermesc/win64-bin`) — compiles the bundle Metro serves
     with **exit 0**, for both the default transform profile and the
     `unstable_transformProfile=hermes-stable` one the client actually requests.
  2. The reported location **moved between attempts** — `349469:56`, then
     `348989:6`, then `351570:97` after a full reinstall. One valid source cannot
     fail in three places.
  3. Read the line it settled on. Bundle line 351570 is
     `enableTimeToInitialDisplayForPreloadedRoutes = _ref$enableTimeToInit2 === void 0 ? false : _ref$enableTimeToInit2,`
     and column 97 lands inside `? false :`. Hermes reports "`':'` expected in
     conditional expression" about a `:` that is right there in the bytes Metro
     sends. The copy the device parsed is not the copy Metro served.
  4. The identical tree had mounted and rendered the feed on the same device
     twenty minutes earlier.

  So the transport or the client's on-disk copy mangles a ~16 MB bundle. `expo
start --clear`, deleting `%TEMP%\metro-cache`, `pm clear`, `adb kill-server`,
  `reverse --remove-all`, Metro's `/reload`, and a full uninstall + reinstall of
  the dev client APK all failed to shift it. A release/embedded build, a physical
  device, or a smaller bundle is the next thing to try.

  Cheap first check next time: `hermesc -emit-binary` the bundle Metro serves.
  Thirty seconds, and it tells you whether to look at the code at all.

- **`/legal/*` copy is three short paragraphs per page.** Counsel-owned, not an
  engineering fix.
- **Mobile screenshots are viewport-only.** The harness cannot scroll, so review
  of long screens (`me/edit`, `settings/notifications`) covers the first screen
  and no further.
- **Mobile console capture is still blind.** `logcat` carries no `ReactNativeJS`
  on this stack; the harness says so loudly rather than writing `{}` and calling
  it clean.
